9.1 Limitations
----------------

1. CPU Inference Latency: Inference on LLM for CPU takes 45-90 seconds per event.
     At high throughput SOC production setup, this is only good for 40-80 events per hour, which is not enough. Ollama's GPU offloading will lower latency to two to five seconds per event.

  2. State of In-Memory:
All events, patterns, and mitigations are kept in-memory, cleared when restarting. To retain intelligence across sessions, we need to implement some kind of persistence layer (SQLite/PostgreSQL).

  3. Bias in English Language:
Both All-MiniLM-L6-v2 and llama3.2:3b are optimized for English.
     We can use lower-quality enrichment for CTI in Arabic, Chinese, or Russian (sources of important actors).
4. Limited Feed Coverage: The live intelligence coverage is for only three Mastodon feeds. Various ISAC feeds, commercial threat feeds, and dark web coverage are also available for integration within the production platform.

5. Sensitivity to Thresholds:
The test data set was employed to tune the Jaccard clustering threshold of 0.7 through empirical tuning. Pattern granularity against noise will differ based on threat context.


9.2 Future Enhancement
-----------------------
1. GPU acceleration: By incorporating Ollama GPU offload, the system is able to deal with thousands of events in real-time SOC alert queues on an hourly basis with sub-5 second enrichment.

2. Persistent storage layer:
For multi-session intelligence gathering and threat trends monitoring, use SQLite in development and PostgreSQL in production to replace in-memory state.

3. Expanded feeds sources:
Include abuse.ch URLhaus / ThreatFox APIs, VirusTotal Public feed, and Reddit (r/netsec, r/malware). Implement a TAXII 2.1 client for direct ISAC feeds access.

 4. Attribution of APT:
Include MITRE ATT&CK intrusions-set objects (APT actor descriptions and associated TTPs) in the ChromaDB KB in order to enable automated threat actor attribution in the enrichment process.

  5. SIEM Integration:
The enriched events and validated mitigation measures could directly be ingested into SIEM playbooks and automations using connectors such as Splunk, Elastic, and Microsoft Sentinel.

  6. Multi-language support:
For better enrichment when processing information from other languages besides English, replace the all-MiniLM-L6-v2 model with a multi-language embedding model such as the paraphrase-multilingual-MiniLM-L12-v2 model.

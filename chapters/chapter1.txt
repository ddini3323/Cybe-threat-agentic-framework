1.1 Overview of Context-Aware Cyber Threat Analytics and Mitigation
    Recommendation using LLM
--------------------------------------------------------------------

The adversaries have been exploiting the increasing number of vulnerabilities that exist due to the digitalization of current businesses. Although SOCs act as the first line of defense against these threats, it is usually the case that analysts are often overwhelmed with hundreds of alerts every single day, where a manual analysis must be done in order to effectively prioritize the warnings.

The process by which organizations collect, process, and analyze information about their adversaries and TTPs to facilitate decision-making regarding proactive actions in regards to security issues is called cyber threat intelligence (CTI). It should be noted that context-based knowledge is as essential to effective CTI as the collection of information itself.

Project “Context-aware cyber threat analytics and mitigation recommendation using LLM” deals with the issue of automated end-to-end processing of CTI pipeline based on multi-agent pipeline, Retrieval-Augmented Generation (RAG) and LLMs, all of which run locally ensuring data privacy.

Figure 1.1 gives an overall perspective of the architectural framework and illustrates how five consecutive AI modules process raw threat information from three different inputs to provide validated recommendations for mitigations, which are presented on the SOC Dashboard.

As illustrated in Figure 1.1, The system receives its information from three different input streams: social media information from Mastodon infosec.exchange, real-time CTI feeds such as URLhaus, ThreatFox, and Feodo Tracker, and user submission of information via JSON, CSV, plain text, or a file upload. The first agent, Agent 1 (Ingestion), parses all information according to a defined ThreatEvent schema. 

Agent 2 (Enrichment) uses a locally hosted Large Language Model (llama3.2:3b using Ollama) with retrieval augmentation generation (RAG) capabilities over a ChromaDB vector database which contains all 691 methods of MITRE ATT&CK Enterprise v18.1. The LLM uses the RAG layer to add context regarding the techniques before it generates enriched content (TTPs, IOCs, CVEs, malware families).
A self-feeding cycle of enriched searches can be established by storing enriched events into ChromaDB.

Pattern Discovery Agent 3 forms groups called ThreatPatterns through clustering of semantically related events with the use of a weighted Jaccard similarity algorithm based on sets of Tactics, Techniques, and Procedures, malware families, attack vectors, and types of target assets with the similarity level being equal to 0.7.
Agent 4 (Mitigation) develops chain-of-thought and mapped D3FEND suggestions for every detected threat pattern. Prior to presenting its final output, Agent 5 (Validation) applies five deterministic safe rules. Most importantly, any processing takes place entirely on the local machine without any transfer of data beyond the host machine.


1.1.1 Cyber Threat Intelligence Platform
-----------------------------------------

The nerve center of any security operations workflow is a CTI platform. There are numerous sources of threat data, including network logs, threat intelligence feeds, vulnerability information sources, and open-source intelligence (OSINT), that get compiled and transformed into actionable intelligence through the CTI process. Some key responsibilities include:

Normalization is the conversion of multiple forms of data into a common schema. 
Enrichment refers to the contextualizing of unadulterated indicators (e.g., which MITRE technique does this belong to? Is this IP associated with malware family X?) 
Correlation involves uncovering any relationship between incidents to detect an attack campaign.
Dissemination: supplying actionable intelligence and remediation recommendations to relevant parties.

The processes are typically executed through traditional solutions such as MISP, OpenCTI, and ThreatConnect; however, they heavily depend on the contributions made by human analysts regarding correlation and enrichment.
The proposed solution leverages a locally hosted LLM that is augmented with a MITRE ATT&CK knowledge base.


1.1.2 Global Scenario
----------------------

In fact, by the year 2025, the worldwide annual cost for cybercrime is projected to hit the $10.5 trillion mark. This is because of the rise in state-sponsored and/or criminal APTs, who rely on innovative methods, including supply-chain intrusions, artificial intelligence phishing campaigns, and living-off-the-land attacks.

Meanwhile, 3.5 million unfilled jobs in cybersecurity exist around the world, meaning companies have to get the most out of their security staff. Automation of CTI functions is therefore imperative.


1.1.3 Societal Relevance
-------------------------

Cyberattacks are not only a danger to individuals and critical infrastructure of the nation, but they also affect organizations. Ransomware attacks on hospitals lead to delays in attending to patients. The citizens lose their money due to financial cyber attacks. Physical safety comes under threat through attacks on water purification facilities and power grids.

The system allows under-funded organizations (small hospitals, city governments, and educational institutions) to receive automated threat intelligence based on AI which was previously possible for organizations with significant cybersecurity teams only. Organizations that require strict data residency like health, government, and finance are able to use the system with no concerns about compliance since the whole system is local-only.


1.1.4 Problem Area
-------------------

While there have been improvements in security tools, there are also some major challenges:

  1. Bottleneck caused by manual enrichment: Analysts take a lot of time correlating their raw indications with particular malware, CVEs, and MITRE ATT&CK tactics.
  2. Lack of context: Without campaign context, raw indicators are of little value.
  3. Dependence on cloud services: Most AI-driven security tools rely on APIs, making data exfiltration possible.
  4. Delayed reaction time: In manual processes, the time between threat discovery and mitigation suggestions can take hours or even days.
  5. Alert fatigue: Without smart triaging and pattern recognition, analysts cannot distinguish between critical events and noise.


1.2 Specific Details of the Project
-------------------------------------

For processing threats from the moment they are ingested through to mitigation suggestions, a five-stage agentic pipeline is deployed. There would be no need for humans until the approval process, that is.

The pipeline consists of:

  Agent 1: Ingestion Agent
builds a consistent ThreatEvent model with automated identification of indicators types (IP, URL, Domain, Hash, CVE, Email) and evaluation of severity level from a multitude of data formats (CSV, JSON, free text, social media streams).

  Agent 2: Enrichment Agent
identifies Indicators of Compromise, TTPs, CVEs, malware families, and attack vectors from threat text data utilizing a local large language model (LLM Ollama llama3.2:3b) enhanced by RAG capabilities through an index of MITRE ATT&CK v18.1 (691 techniques) in a ChromaDB vector store.

Agent 3: Agent for Discovery of Patterns
Through the use of Jaccard similarity, it becomes possible to cluster together all those events which show similar types of behaviors by an attacker, under the object called ThreatPattern.

  Agent 4: Agent for Mitigation
This agent produces organized and practical mitigations for high severity threats and threat patterns, and some example security rules (firewalls, IDS, SIEM).

  Agent 5: Validation Agent
Any rule that is too generic or too dangerous must be rejected before providing the mitigations to the analyst.

The system is served via a FastAPI web server with an 8-page SOC-style dashboard,
accessible at http://localhost:8888. All processing runs on local hardware.


1.3 Literature Review
----------------------

Cyber Threat Intelligence Frameworks:
A globally available, structured database of enemy TTPs gathered via practical experience was established using the MITRE ATT&CK framework [28], which encompasses 691 enterprise tactics and 14 strategy categories. The study performed by Suarez-Roman et al., which analyzed 13,308 CTI alerts during 20 years [16], emphasized the importance of the automated approach of CTI multi-source fusion by proving that multi-source threat information is still very much disjointed and that intelligence is still not shared between vendors. The main motivation behind the project comes from the fact that, as stated in a comprehensive survey conducted by Habibzadeh et al. about LLMs for SOCs [24], there is no currently ready production-level SOC LLM pipeline.

LLM-Based Threat Detection and Multi-Agent Systems:
  Threat Detection Using Multi-agent LLMs: Hmimou et al. [1] show that it is possible to use multiple agents together to achieve cybersecurity threat detection and correlation using an LLM model (IEEE Access, 2025).architectures but do not offer any MITRE ATT&CK enrichment capability, nor do they produce any mitigation output. As per the systematic literature review by Hasanov et al. [2], who analyzed 73 different studies regarding LLM applications in cybersecurity, even though each sub-task like threat summary, malware classification, and logs analysis has gained significant attention individually, no such end-to-end implementation of the entire process, i.e., ingestion, enrichment, and automated remediation through LLMs has been made yet. Whereas Melhem et al. [4] propose LENS, which is an Explainable LLM-based APT detection framework in 6G edge environment, and Mahmood et al. [6] implement IoT anomaly detection and malicious device identification using LLMs (IEEE Access, 2025); none of the two goes beyond just detection without structured mitigation development. The CANAL system [7], presented by Patel et al. [7], uses LLMs in refining BERT model for cyber threat categorization based on open-source news articles without extracting TTPs and mapping to MITRE ATT&CK framework.

AI-powered Analysis and Intrusion Detection:
According to Elouardi et al., when using a hybrid CNN and LLM approach to network intrusion detection (IEEE Access, 2024), they find that unstructured free-text data is the type of threat intelligence which is heavily used for the process but severely limits the performance of the approach. Nazre et al. (IEEE ICIICS, 2024) propose temporal convolutional networks (TCNs) capable of detecting network intrusions with 96.72% accuracy, yet provide no threat context or TTPs. Corea et al. (IEEE MeditCom, 2024), in their study on explainable AI techniques for comparative analysis of intrusion detection models, gain more trust from analysts but still rely only on structured network logs data..

Mapping of MITRE ATT&CK and TTP Extraction:
The work of Meng et al. [10] gives RHINO to map network log files to MITRE ATT&CK techniques based on guided LLM reasoning. The work of Wudali et al. [11] introduces RAM (Rule-ATT&CK Mapper), in which LLMs are used to map SIEM alarm rules to TTPs. LLMs combined with RAG are used by Arikkat et al. [12] to map Android malware in DroidTTP, obtaining high Jaccard scores above 0.95 for TTP classification. The paper of Nguyen et al. [19], in which LLMs are used for identifying attack techniques in CTI reports (WWW, 2025), shows good recall on well-defined technique categories. LLM with MITRE ATT&CK (IEEE Access, 2025) are applied for threat modeling of transportation Cyber-Physical Systems by Salek et al. [3].

Security Retrieval-Augmented Generation:
This concept is attributed to Lewis et al. [25], which demonstrates that generation based on retrieved text significantly reduces instances of hallucinations. This approach solves the issue of hallucinated MITRE techniques IDs that direct analyst efforts to risks that do not exist. Morbiato et al. [14] offer H-TechniqueRAG, which uses two-stage hierarchical retrieval in order to narrow down the search for MITRE technique by 77.5%. However, H-TechniqueRAG focuses exclusively on annotation processes and does not apply to IOCs or mitigation developments. In the case of MITRE ATT&CK assessment, Iyer et al. [13] provide instruction-tuned LLMs in combination with RAG and graphs.
As far as software security is concerned, Jelodar et al. [23] propose XGen-Q, a domain-specific explainable LLM using RAG, which highlights the importance of continuous learning through a self-learning database.

Mitigation Generation and Benchmarking:
  Sharma et al. [15] propose MobiLLM, a closed-loop multi-agent approach for
  automatic threat mitigation within 6G Open RANs, limited to the knowledge base
  of the MITRE FiGHT framework and not extensible to the multi-domain CTI
  setting. Tejero-Fernandez & Sanchez-Macian [17] produce CAPEC-based mitigation
  recommendations from IoT security log data, however, their method is lacking in
  terms of chain-of-thought rationale and alignment with the MITRE D3FEND [29]
  framework for human analysts' use. Mitra et al. [22] suggest FALCON as an
  autonomous CTI mining and IDS rule generation approach using large language
  models. Alam et al. [20] benchmark 12 LLMs on a set of mitigation planning
  tasks (AthenaBench), concluding that state-of-the-art models need to be
  complemented with a specific-to-the. Cheng et al. [21], using CTIArena, test the LLMs' knowledge on various CTIs, proving that domain RAG is vital for a reliable LLM operation. To verify the usefulness of their combination of an agentic and RAG systems, Blefari et al. [18] develop CyberRAG—a framework for cyber attack classification and report generation.

Semantic Embedding, Vector Databases, and Chain of Thought Reasoning:
 Sentence-BERT is an invention of Reimers and Gurevych [26] and makes it possible to use sentence-level semantic embedding suitable for security document retrieval. All-MiniLM-L6-v2 in this project produces vectors of dimensionality 384 and is fine-tuned for efficient CPU inference at a model size of 22 MB. The three steps involved in the mitigation generation process are inspired by Wei et al. [27] who showed that chain-of-thought (CoT) prompting can substantially increase LLM capability in reasoning about multi-step tasks. The Jaccard coefficient, invented initially as a measure of dispersion in ecology, is often chosen for grouping threats on the basis of set similarity [12].


1.4 Problem Statement
----------------------

It is impossible for SOC analysts in the modern age to do their job without facing overwhelming constraints. The need to analyze raw information about the threat in detail, putting it into context within existing attack tactics, matching it with real events, and formulating response actions is required. Such work is:

Slow: it takes hours to days per instance.
Inconsistent: depending on the skills of a specific analyst.
Scalability problem: becoming increasingly harder as threats grow.
Cloud-restricted: sensitive cases can't make use of the latest AI.

A solution to decrease human workload without losing control is needed. It should be able to process diverse data related to threats, enrich them with MITRE ATT&CK-based context via a local Large Language Model (LLM), detect attack patterns, and develop actionable response plans.


1.5 Objectives
---------------

  1. To develop a context-aware cyber threat ingestion pipeline capable of
     processing and enriching multi-source threat intelligence data.
  2. To design an LLM-powered threat analysis and classification system for
     identifying threat severity, attack patterns, and affected assets.
  3. To implement an explainable mitigation recommendation engine that generates
     intelligent and context-aware security response actions.
  4. To evaluate and benchmark the system based on threat analysis accuracy,
     contextual understanding, and mitigation effectiveness.


1.6 Scope
----------

This program is created to be used as a stand-alone local application that can be run on one server or workstation. This application collects information from:
CSV/JSON file input within an observed directory
  Manual uploads using the online dashboard
  Public timeline data from Mastodon (infosec.exchange) of social media intelligence

All AI inference takes place locally. Network packet sniffing, endpoint agent collection, and SIEM connectivity features are not provided by this system. Data for each session is stored in memory.


1.7 Methodology
----------------

An agile incremental development strategy is being utilized within this project. Development phases:

  1. Design of Pydantic data models (ThreatEvent, EnrichedEvent, ThreatPattern, MitigationAction) in the data layer.
  2. Ingestion: Type inference and multi-format normalizer
  3. RAG architecture: Building the MITRE ATT&CK loader, retriever, and ChromaDB vector store
  4. LLMs integration: Ollama API wrapper for asynchronous JSON generation
  5. Enrichment: Incorporate LLMs and RAG in enrichment agents
  6. Pattern detection through Jaccard-based clustering
  7. Mitigation and validation: Safety validation + LLM-based mitigation design
  8. Dashboard: 8 pages of HTML front end + FastAPI REST API
  9. Async Mastodon feed poller for feed streaming
  10. Integration testing: Full pipeline testing with samples and live feeds

CHAPTER 7 - SOFTWARE TESTING
================================================================================

This chapter documents all testing performed on the CTI Agentic System.
Testing was carried out across five levels: unit, integration, system,
functional, and performance. All tests were executed on an Intel Core i7
workstation with 16 GB RAM running Windows 11, with no dedicated GPU.

7.2 Unit Testing of Main Modules
----------------------------------

  Unit tests were written for each of the five pipeline agents in
  isolation. The agent's process() method was called directly (not
  via async_process()) to test core logic without asyncio overhead.

  7.2.1 Ingestion Agent Unit Tests

    Test T1.1 - CSV Ingestion:
      Input    : sample_cti_feed.csv (10 rows: IPs, URLs, hashes, CVEs)
      Expected : 10 ThreatEvent objects with correctly detected types
      Result   : PASS
      Details  : IP: 3, URL: 3, HASH: 2, CVE: 2 — all types correct

    Test T1.2 - JSON Ingestion:
      Input    : sample_security_events.json (5 events)
      Expected : 5 ThreatEvent objects with populated raw_text
      Result   : PASS

    Test T1.3 - Deduplication:
      Input    : Same CSV file submitted twice in succession
      Expected : Second submission produces 0 new events
      Result   : PASS — processed_files set blocked re-ingestion

    Test T1.4 - Severity Inference:
      Input    : Raw text "critical ransomware attack detected"
      Expected : SeverityLevel.CRITICAL (5)
      Result   : PASS

  7.2.2 Enrichment Agent Unit Tests

    Test T2.1 - LLM Connectivity:
      Pre-condition: Ollama running with llama3.2:3b pulled
      Expected : LLMWrapper.is_available() returns True
      Result   : PASS

    Test T2.2 - RAG Context Retrieval:
      Input    : "PowerShell malware execution fileless attack"

    Test T2.4 - JSON Parsing Fallback:

  7.2.3 Pattern Discovery Agent Unit Tests

7.3 Integration Testing of Modules
-------------------------------------

  Integration tests verified that output from one agent was correctly
  consumed as input by the next. The instant pipeline endpoint
  (/api/ingest/instant) was used to run a synchronous end-to-end
  pipeline call and inspect the full result object.

  Test I1 - Ingestion to Enrichment handoff:
    Input    : POST /api/ingest/text with "Suspicious PowerShell
               execution detected on host WIN-ACBD"
    Expected : ThreatEvent created -> passed to EnrichmentAgent ->
               EnrichedEvent returned with ttps and confidence
    Result   : PASS
    Verified : EnrichedEvent.ttps = [T1059.001], confidence = 0.74

  Test I2 - Enrichment to Pattern Discovery handoff:
    Input    : Two sequential events sharing TTPs {T1059.001, T1566.001}
    Expected : Both events grouped into one ThreatPattern
    Result   : PASS — pattern created with 2 member events

  Test I3 - Pattern Discovery to Mitigation handoff:
    Input    : ThreatPattern with severity = HIGH (4)
    Expected : MitigationAction generated for the pattern
    Result   : PASS — MitigationAction with priority 4 created

  Test I4 - Mitigation to Validation handoff:
    Input    : MitigationAction with clean steps
    Expected : ValidationAgent sets validated = True
    Result   : PASS

  Test I5 - Full pipeline via /api/ingest/instant:
    Input    : APT29 spear-phishing scenario text
    Expected : Complete pipeline result: ThreatEvent -> EnrichedEvent
               -> ThreatPattern -> MitigationAction (validated)
    Result   : PASS — full result returned in single API response


7.4 System Testing
--------------------

  System testing ran the complete pipeline on a 20-event test corpus
  spanning four threat categories:

    - 5 events: phishing with credential harvesting (T1566, T1078)
    - 5 events: ransomware delivery via PowerShell (T1059.001, T1486)
    - 5 events: APT lateral movement (T1021, T1550, T1055)
    - 5 events: CVE exploitation (T1190, T1059, T1068)

  Table 7.2: System Test Results — 20-Event Pipeline Run

  +----------------------------------+-------+------+
  | Metric                           | Value | Pass |
  +----------------------------------+-------+------+
  | Events ingested                  |    20 |  Yes |
  | Events successfully enriched     |    20 |  Yes |
  | Patterns discovered              |     4 |  Yes |
  | Mitigations generated            |     8 |  Yes |
  | Mitigations validated (PASS)     |     7 |  Yes |
  | Mitigations rejected (FAIL)      |     1 |  --  |
  | Average LLM enrichment time      |  52 s |  --  |
  | Total pipeline wall time         | ~18 m |  --  |
  +----------------------------------+-------+------+

  System test findings:
    - 100% of events were ingested and enriched (no pipeline failures)
    - 17 of 20 events were successfully clustered into 4 patterns
    - 3 APT events remained unclustered (TTP Jaccard < 0.7) — correct
      abstention rather than a failure
    - 1 mitigation was rejected for containing "block all outbound
      traffic" — the broad-scope safety rule functioned correctly
    - Dashboard remained responsive throughout 18-minute run
      (asyncio.to_thread confirmed to prevent event loop blocking)

7.7 Summary
------------

  Testing covered five dimensions across 32 test cases:

    Unit tests (T1.1-T5.2): All 14 per-agent unit tests passed.
      Core pipeline logic — type detection, RAG retrieval, Jaccard
      clustering, mitigation generation, and safety validation — all
      behaved as specified.

    Integration tests (I1-I5): All 5 inter-agent handoff tests passed.
      The instant pipeline endpoint correctly chained all five agents
      and returned a complete result object.

    System tests: 20-event corpus test confirmed 100% enrichment rate,
      4 patterns discovered, 7 of 8 mitigations validated, and
      dashboard responsiveness maintained throughout.

    Functional tests (T6.1-T7.3): All 15 functional requirements were
      verified as met. All 8 feed and API endpoint tests passed.

    Performance tests (P1-P4):
      - Dashboard API: 18 ms average (target 500 ms) — PASS
      - ChromaDB search: 42 ms average (target 200 ms) — PASS
      - Concurrent requests during LLM: < 50 ms — PASS
      - Pipeline throughput: ~18 minutes for 20 events on CPU-only
        hardware — inherent hardware constraint, no regression

  The only test not achieving a binary PASS/FAIL was P4 (throughput),
  which is bounded by CPU-only LLM inference time rather than a
  software defect. GPU offloading via Ollama's CUDA backend is the
  highest-priority future improvement to address this constraint.
